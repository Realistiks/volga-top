# Как устроен сайт и код команды St.Code

Этот файл - подробное пояснение к репозиторию. Короткая версия для жюри лежит в
`README.md`, здесь разбирается каждый компонент и связь между ними.

## 1. Общая идея

Сайт статический: `index.html` + CSS + JavaScript. Сервер нужен только для чата.
Локально и в Docker сайт отдаёт `bot/bridge.py`, на публикации работает GitHub Pages.
Основной репозиторий - GitVerse, GitHub используется как зеркало.

## 2. Разметка: `index.html`

- `header` - название команды, теги, обратный отсчёт, кнопка переключения темы.
- `nav` - липкая навигация с якорями на все разделы.
- `#about` - описание решения и четыре показателя.
- `#team` - сетка из пяти равных карточек участников. Фотографии кликабельны и
  открываются в полноэкранном просмотре.
- `#roles` - цикл работы команды: промт, разработка, съёмка и монтаж, аудит, сборка, сдача.
- `#idea` - три карточки под критерий «Оригинальность и инновационность»: новизна,
  самостоятельность, потенциал развития.
- `#prompt` - конструктор промтов: при смене участника меняется список задач.
- `#ai` - раскрытие использования ИИ по п. 9.2 положения.
- `#contacts` - ссылки на GitVerse, GitHub-зеркало и олимпиаду ПГУТИ.
- `#particles` - canvas для шлейфа за курсором, линия поверх контента, но с
  `pointer-events: none`, поэтому не мешает кликам.
- Чат: кнопка `#chat-toggle`, панель `#chat-panel`, быстрые вопросы и форма.

Комментарии в HTML помечают зоны ответственности участников.

## 3. Стили

### `css/style.css`
Базовая тема: тёмная. Все цвета вынесены в CSS-переменные в `:root`:
`--bg`, `--card`, `--border`, `--text`, `--muted`, `--accent`, `--blue`, `--chip`,
`--nav-bg`, шрифты `--font-body` и `--font-head`.

Блок `[data-theme="light"]` переопределяет те же переменные для светлой темы.
По умолчанию атрибут `data-theme` не задан, поэтому сайт всегда стартует в тёмной теме.
Кнопка переключателя просто ставит или убирает этот атрибут.

Основные классы: `.wrap` - контейнер, `.metric` - показатели, `.member-card` - карточка
участника, `.team-grid` - сетка команды, `.step` - шаг процесса, `.chip` - маленькая метка,
`.result` - выделенный вывод, `.reveal` - анимация появления при скролле.

### `css/extra.css`
Дополнительные блоки: переключатель темы, чат, конструктор промтов, обратный отсчёт,
нити партиклов и адаптив для мобильных. Все цвета тоже берутся из переменных,
поэтому обе темы выглядят цельно.

## 4. Скрипты

| Файл | Что делает |
| --- | --- |
| `js/main.js` | Через `IntersectionObserver` добавляет класс `in` к элементам `.reveal`, когда они входят в экран. Отвечает за полноэкранный просмотр фото и закрытие по Esc |
| `js/particles.js` | На `mousemove` и `touchmove` создаёт точки, соединяет близкие линии и плавно гасит их в `requestAnimationFrame`. Отключается при `prefers-reduced-motion` |
| `js/theme.js` | По клику ставит/снимает `data-theme="light"`, обновляет `aria-pressed` и meta theme-color. Ничего не сохраняет, поэтому после reload снова тёмная |
| `js/answers.js` | Массив `TEAM_ANSWERS`: готовые ответы на базовые вопросы о команде. Функция `findBasicAnswer` ищет совпадение по ключевым словам |
| `js/chat.js` | UI чата. Сначала ищет базовый ответ локально. Если его нет, отправляет POST `/ask` на мост. Показывает «Удалённый чат неактивен», если endpoint недоступен |
| `js/idea.js` | Обратный отсчёт до 27.11 23:59 МСК, персональные промты для пяти участников и опрос `/health` при открытии чата |
| `js/config.js` | Адрес удалённого моста. Меняется скриптом `bot/start_remote.py` |

## 5. Мост: `bot/bridge.py`

Стандартный `http.server` на порту 8765. Эндпоинты:

- `GET /` и статические файлы - отдаёт сайт, чтобы локально всё работало одним адресом;
- `GET /health` - состояние сервера и доступность сессии OpenCode;
- `POST /ask` - принимает `{"question": "..."}`.

Порядок обработки вопроса:

1. Ответ из `BASIC_ANSWERS` если вопрос базовый - отдаётся сразу, без агента.
2. Проверка темы через регулярное выражение `TOPIC_RE`. Всё не по теме команды
   отклоняется текстом `REFUSAL`.
3. Проверка доступности сессии OpenCode через `/api/session/<id>`.
4. `POST /api/session/<id>/prompt` с инструкцией отвечать кратко и не трогать файлы.
5. `POST /api/experimental/session/<id>/wait` - ждём окончания ответа.
6. `GET /api/session/<id>/message` с параметрами через `--param`, берём последний
   текст ассистента и возвращаем в чат.

Если агент недоступен или запрос упал, возвращается «Удалённый чат неактивен».
Адрес OpenCode берётся из `OPENCODE_BIN`, сессия - из `OPENCODE_SESSION_ID`,
хост и порт - из `CHAT_BRIDGE_HOST` и `CHAT_BRIDGE_PORT`.

## 6. Удалённый режим: `bot/start_remote.py`

Поднимает мост и, если нужно, быстрый HTTPS-туннель cloudflared. Полученный адрес
записывается в `js/config.js`. Флаг `--push` отправляет обновлённый конфиг на GitHub,
чтобы живая версия сайта сразу видела новый endpoint. Ctrl+C останавливает мост.

## 7. Контейнер

`Dockerfile` берёт `python:3.11-slim`, копирует проект и запускает `bot/bridge.py`.
`docker-compose.yml` пробрасывает порт 8765. Внутри контейнера нет CLI OpenCode,
поэтому живые ответы агента недоступны, но базовые ответы работают.

## 8. Как менять контент

- Имя и роли участников: `index.html` (`#team`), `README.md`, `js/answers.js`,
  `bot/bridge.py`, `js/idea.js`.
- Фотографии: заменить файлы в `assets/img/`, сохранив имена.
- Базовые ответы чата: `js/answers.js` и дубль в `bot/bridge.py`.
- Промты: объект `roles` в `js/idea.js`.
- Публичный адрес моста: `js/config.js`.
- Цвета и шрифты: переменные в `css/style.css`.

После любого изменения запушить в GitHub и переимпортировать репозиторий в GitVerse,
чтобы основной репозиторий и зеркало совпадали.
